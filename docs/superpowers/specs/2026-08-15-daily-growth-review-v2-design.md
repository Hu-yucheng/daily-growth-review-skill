# Daily Growth Review v2 设计规格

## 1. 目标

把当前面向单一预设用户画像的复盘能力，升级为任何用户都能根据自身身份、目标、限制和生活环境使用的通用复盘 Skill。v2 必须将反思转化为可验收的次日行动，同时保留情绪理解、证据评分、知识回忆和长期趋势能力。

核心原则：公开仓库只定义方法和数据结构，不保存任何真实用户的背景、日记、Notion 标识或私人知识库。

## 2. 发布范围

### v2 核心版本包含

- 通用 Codex Skill。
- 同步的 Claude 与 DeepSeek 指令版本。
- 首次使用的分阶段画像流程。
- 画像字段规范和本地私人配置约定。
- 昨日承诺验收、同类情境比较和复发处理。
- 一个主目标、最多两个辅助任务的次日执行板。
- 有证据锚点的行为评分、相对进步值和七日趋势。
- 延迟费曼回忆队列。
- 手机碎片与知识链接的统一 Inbox 数据契约。
- README、示例、测试场景和隐私检查。

### v2 核心版本不包含

- 监听个人微信账号。
- 部署企业微信或微信公众号服务器。
- 硬编码 Notion 数据库 ID。
- 自动读取任意抖音视频的字幕或完整内容。
- 将个人 `second-brain/`、每日复盘或本地画像提交到 GitHub。
- 同时重做实验性 Web App。

微信、Notion、定时任务和网页端在核心方法稳定后作为独立连接器推进。Skill 只在对应工具真实可用且用户授权时调用连接器。

## 3. 架构

```text
公开通用核心
  ├─ 画像访谈与路由
  ├─ 每日/周/阶段复盘
  ├─ 明日执行板
  ├─ 证据评分与比较
  ├─ 延迟回忆队列
  └─ Inbox 数据契约

本地私人层（不进入 Git）
  ├─ 用户画像
  ├─ 自选导师或思想框架
  ├─ 当前目标与现实限制
  ├─ 每日复盘和知识卡
  └─ 平台连接信息

可选连接器
  ├─ Notion
  ├─ Scheduled Tasks
  ├─ 企业微信/公众号
  └─ 其他移动端入口
```

公开 Skill 不应因为私人画像不存在而拒绝复盘；它应先完成最小画像，再输出带不确定性标记的有用初稿。

## 4. 分阶段用户画像

### 首次必问四项

1. 当前主要身份或生活阶段，可多角色并存。
2. 当前最重要的 1–3 个目标。
3. 现实限制与可用资源，包括时间、精力、环境和支持系统。
4. 反馈偏好与分析边界，包括温和、直接或严厉模式。

每次只问一个聚焦问题；如果用户已经自然提供答案，不重复询问。

### 条件式选问

- 年龄段：仅当发展阶段、健康或责任差异会改变建议时询问。
- 学习或工作领域：问领域和职责，不默认要求具体单位名称。
- 家庭环境：只问它怎样影响时间、责任、情绪或决策，不要求家庭成员隐私。
- 身体与健康限制：可选、可跳过，不作诊断。
- 财务和居住条件：仅当目标执行确实依赖这些条件时询问。
- 文化、宗教或价值观：仅在用户主动提出或价值冲突影响复盘时使用。

画像分为两层：

- 稳定层：主要角色、价值偏好、反馈方式、禁止分析的边界。
- 当前周期层：未来 2–12 周目标、时间资源、现实限制、支持系统和比较基线。

当前周期发生明显变化时更新；不机械地每次重问。所有画像内容允许用户查看、修正、跳过或删除。

## 5. 通用复盘视角

公开版取消固定的具名导师。默认只使用四种通用视角：

- 行动一致：知道、承诺和实际行为是否一致。
- 系统改进：问题来自能力、机会、动机、环境还是任务设计。
- 精力可持续：身体和情绪状态是否支持持续行动。
- 学习迁移：是否形成可解释、可复用、可迁移的新理解。

导师、榜样或思想家是私人画像中的可选镜像。用户未选择时不得擅自添加。

## 6. 每日数据流

1. 加载私人画像；不存在时完成首次四项最小画像。
2. 读取最近一次复盘和未验收承诺。
3. 收集当天主线以及高置信碎片，不让噪声日志替代用户自述。
4. 验收旧承诺：`completed / partial / missed / unknown`。
5. 提取事件之心、行为证据、情绪机制和复发次数。
6. 选择上一次相似情境进行成长比较；找不到时标记 `baseline_missing`。
7. 形成一个明日主目标和最多两个辅助任务。
8. 把主目标拆成 3–5 个有权重、完成证据和时间块的子目标。
9. 将需要延迟回忆的学习点加入 1/3/7/30 天队列。
10. 输出人类可读复盘和机器可读索引字段。

## 7. 明日执行板

主目标必须包含：

```yaml
primary_outcome:
definition_of_done:
estimated_effort:
scheduled_block:
dependencies:
minimum_version:
first_physical_action:
if_then_plan:
subtasks:
  - title:
    weight:
    evidence:
support_tasks: []
```

规则：

- 子任务 3–5 个，权重总和必须为 100。
- 进度等于已通过验收的子任务权重之和，不由 AI 主观估计。
- 部分产出只有在完成证据中预先定义了部分验收条件时才计入进度。
- 辅助任务最多两个，只记录完成状态，不抬高主目标进度。
- 任务过大时缩小完成定义或降低为最低版本，不无限拆分。
- 任务受外部依赖阻塞时记录 `blocked`，不得伪装为用户执行失败。

## 8. 评分与成长比较

每个用户只启用与其目标有关的 4–6 个维度。通用候选维度为：承诺闭环、专注执行、身体精力、情绪调节、学习迁移、关系责任。

### 行为证据分 0–4

| 分数 | 锚点 |
|---:|---|
| 0 | 没有证据，或出现明确倒退与损害。 |
| 1 | 能识别问题，但没有形成有效行动。 |
| 2 | 有部分行动或结果，但未达到完成定义，或严重依赖推动。 |
| 3 | 独立达到预先定义的完成标准。 |
| 4 | 达标且出现质量、独立性、迁移、效率或可持续性的明确提升。 |

### 相对进步值 -2 至 +2

默认比较上一次相似情境，而不是机械比较昨天：

- `-2`：明显退步。
- `-1`：轻度退步。
- `0`：没有可证实变化或数据不足。
- `+1`：出现一个可证实的新改进。
- `+2`：改进稳定、可迁移或在更困难条件下仍成立。

同时输出七日趋势：`rising / stable / falling / insufficient_data`。不同类型日子不能被强行汇总成一个虚假的综合分。

## 9. 延迟费曼反馈

当天的 AI 生成稿不算掌握证据。真正的状态只能是：`未开始 / 已回忆 / 已口述 / 已录音 / 已教给别人 / 已迁移应用`。

回忆流程：

1. 第二天先提出 1–3 个回忆问题，不展示原答案。
2. 用户回答后，对比遗漏、误解和迁移情况。
3. 生成“昨日升级卡”：旧反应、新反应、有效机制、证据、下一次迁移线索。
4. 重要内容在第 3、7、30 天再次抽查；普通内容默认只做第 1 天回忆。

提醒只能在平台存在 Scheduled Tasks 或等价能力、用户明确同意并给出时间时创建。若依赖本地文件，必须说明设备和应用运行条件。

## 10. 手机碎片与第二大脑

所有入口统一写入 Inbox：

```yaml
capture_id:
captured_at:
source:
type: thought | task | link | audio | event | learning
raw_content:
context:
confidence:
processed: false
```

处理规则：

- 用户自述是主线，聊天、录音转写和链接是补丁。
- 链接必须保留来源；无法读取内容时不得根据标题编造摘要。
- 抖音等受限内容无法获取全文时，请用户提供字幕、口述要点或截图。
- 有价值碎片转为知识卡、问题卡或行动卡；娱乐内容明确标记，不伪装成学习。
- 每日复盘只引用与当天主线相关的卡片，不把所有收件箱内容全部塞入复盘。

## 11. 隐私与 GitHub 边界

- `second-brain/`、真实画像、每日复盘、Notion ID、Webhook、Token 和本地连接配置不得进入公开提交。
- 公开仓库只提供示例占位符和 schema。
- 示例不得使用具体职业、专项申请、关系人物或其他可识别的个人经历作为默认背景。
- 发布前扫描姓名、单位、数据库 ID、Webhook、Token、具体个人目标和私人日记关键词。
- 当前脏工作区中的用户修改必须保留；只提交经过明确检查的 v2 文件。

## 12. 错误处理

- 背景不足：先问最小问题，仍不足时输出草案并标记不确定性。
- 无旧复盘：跳过承诺验收并建立首个基线。
- 无相似事件：相对进步写 `baseline_missing`，不得臆造进步。
- 任务权重不等于 100：在输出前自动归一或重新分配，并说明调整。
- 链接不可访问：保留原链接和失败原因，请求补充材料。
- 连接器不可用：输出可复制内容，不声称已写入或已提醒。
- 情绪风险：保持反思性假设，禁止诊断和羞辱；即时危险时切换到现实安全支持。

## 13. 测试策略

修改前运行无 v2 指导的基线场景，记录失败形态；修改后用相同场景前测与复测。

至少覆盖：

1. 与科研无关的高中生首次使用，不应出现科研或固定导师。
2. 有照护责任的职场人，不应强迫披露完整家庭隐私。
3. 明日目标过大，必须拆成权重为 100 的可验收任务。
4. 忙碌但没有结果的一天，不应获得高执行分。
5. 与昨天不可比的事件，应寻找同类基线或标记缺失。
6. 用户只发送抖音链接但内容不可读，不得编造知识卡。
7. 没有连接器时，不得声称已写入 Notion、微信或创建提醒。
8. 第二天费曼检查必须先让用户回忆，再展示对照。
9. 私人目录、Notion ID、Webhook 和真实画像不能出现在待提交文件中。

结构验证包括 YAML frontmatter、引用路径、Markdown 围栏、Codex/Claude/DeepSeek 方法一致性、隐私扫描和 Git diff 审计。

## 14. 完成标准

v2 只有在以下条件同时满足时才可发布：

- 公开版本没有单一职业、科研、固定导师或个人目标默认值。
- 最小画像能驱动个性化维度和建议。
- 明日主目标可以计算可解释的 0–100% 进度。
- 评分同时包含行为证据、同类情境变化和趋势边界。
- 延迟回忆不会把 AI 生成文本误计为掌握。
- Inbox 和连接器边界明确，不虚构平台能力。
- 基线与前向测试通过。
- Git 提交不包含私人数据和无关用户修改。
